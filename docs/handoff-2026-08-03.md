## What landed this session, that you should not re-derive

Five mechanisms now exist and will fire at you if you break them:

1. **`coverage.coverageBySet` / `COMPLETE_SETS`** — the two completeness gates are
   per set. They still NAME cards; only the scope moved.
2. **`isKnownBracketToken` + `NON_KEYWORD_BRACKETS`** (`model/keyword.ts`) — a
   bracketed token nothing consumes fails the suite, naming the token and every
   card printing it.
3. **`HIDDEN_KEYWORD_FALSE_POSITIVE_DEF_IDS`** — keyed by defId now, like every
   other per-card loader table. `isGenuinelyHidden` is exported for the synthetic
   reprint test.
4. **Loader censuses** — supertype, rarity, the `DOMAINS` order, the 12 split-pip
   candidates, and the five cards printing "I enter ready". Each is a list that
   fails when the pool changes, on purpose: adding a set is meant to make several
   of these go red at once, and each red is a decision, not a bug.
5. **`definitionFor` throws on an unregistered decision kind** — engine and AI
   both. A registered definition returning NO OPTIONS is still legitimate and
   still dropped; the two cases are separable and both are pinned.
